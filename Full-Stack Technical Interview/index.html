#1 JavaScript — Async Flow

How does the event loop determine execution order?

Synchronous code runs first. The event loop then processes microtasks, such as Promise callbacks, before moving to macrotasks, such as setTimeout() callbacks. Fetch responses are handled asynchronously, so their order depends on when they arrive.

What is the difference between a microtask and a macrotask?

Microtasks include Promise callbacks, while macrotasks include setTimeout() and setInterval() callbacks. Microtasks run before the next macrotask.

Why can blocking synchronous JavaScript freeze the UI?

Blocking code must finish before JavaScript can handle user clicks or UI updates, so the page feels unresponsive until the work completes.

#2 React — Unnecessary Re-renders

How would you investigate and reduce unnecessary re-renders?

Use the React DevTools Profiler to identify re-rendering components, then optimize only the components causing a measurable performance issue.

When would React.memo help?

Use React.memo when a child frequently receives the same props and does not need to re-render.

What do useMemo and useCallback solve?

useMemo caches a calculated value, while useCallback caches a function reference. Avoid memoizing everywhere because it adds complexity and has its own cost.

#3 REST API + Express — Request Flow

How would you debug a 401 error?

Check that the frontend sends the authentication token, then verify that the backend receives and validates it. Use the browser Network tab and backend logs to find missing, expired, or invalid tokens.

Where should authentication middleware run?

It should run before the controller so the request is authenticated before business logic executes.

app.get("/api/profile", authMiddleware, profileController);

What is the difference between 401 and 403?

401 Unauthorized means the user is not properly authenticated. 403 Forbidden means the user is authenticated but does not have permission to access the resource.

#4 MongoDB + Mongoose — Duplicate Data

How would you prevent duplicate registrations?

Check whether the email exists, and create a unique index so MongoDB enforces uniqueness even when requests arrive at the same time.

userSchema.index({ email: 1 }, { unique: true });

Is application-level checking alone sufficient?

No. Two requests can both check that an email is available before either inserts it. This race condition requires database-level protection.

How should the API respond to a duplicate-key error?

Catch MongoDB's E11000 error and return HTTP 409 Conflict with a clear message.

res.status(409).json({ message: "Email is already registered" });
#5 Authentication + Authorization + ImageKit

What checks should happen before granting access?

Verify the student's token with authentication middleware, then check that the requested resource belongs to that student. For uploads, also validate file type, size, and upload permissions.

What information should the server trust?

Do not blindly trust user IDs, roles, or permissions from the client. Use the verified token and trusted server-side data to determine identity and permissions.

How do you prevent changing an ID in the URL?

Compare the resource owner ID with the authenticated user's ID from the verified token.

if (resource.userId.toString() !== req.user.id) {
  return res.status(403).json({ message: "Access denied" });
}

Where does ImageKit fit into the upload flow?

ImageKit stores and delivers files. The backend verifies identity and upload permissions, provides authorized credentials or handles the upload securely, and prevents users from overwriting or accessing another user's private files.
